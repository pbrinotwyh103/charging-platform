# 第二阶段大数据与智能分析平台全量实现设计

## 1. 目标与完成定义

本设计覆盖《第二阶段大数据与智能分析项目需求文档》的 P0、P1、P2 全部范围。在仓库内，每项需求必须同时具备实现代码、自动化检查或可重复验收步骤、运行文档和需求追踪状态，才可标记完成。依赖 Hadoop、Spark、HDFS 或浏览器目标屏幕的条目必须由验收脚本生成机器可读结果；未实际运行的外部环境检查保持“待环境验收”，不得以模板代替证据。

## 2. 实施边界与阶段划分

全量工作拆为六个可独立验收的子项目：

1. 数据与数仓可信链路：数据批次、源快照、六维质量规则、清洗隔离、ODS/DWD/DWS/ADS、级联影响与幂等验证。
2. 模型生命周期：多模型训练、时间切分、统一评估、自动选择、版本登记、置信区间、长周期预测和漂移检测。
3. 分析服务与大屏：统一 API 响应、认证、筛选、刷新、缓存、离线资源、多租户与监管专题。
4. Qt 智能联动：用户预测筛选与推荐解释、管理员预警筛选与合并、调度排班、维护和扩容建议。
5. 准实时运行与安全：增量特征刷新、任务调度、审计、目录权限、脱敏、边界限制和故障降级。
6. 验收与交付：一键环境检查、端到端运行、视觉回归、性能与稳定性检查、证据归档和需求矩阵自动汇总。

各子项目只通过稳定文件契约和 API 契约通信，避免分析故障影响第一阶段找桩、预约、充电、计费和设备控制。

## 3. 数据架构

每次运行创建唯一 `batchId`，记录来源、输入摘要、接入时间、记录数和 schema 版本。原始数据写入 ODS；规则检测输出问题明细和规则汇总；清洗结果分别进入有效数据与 quarantine；DWD、DWS、ADS 均携带 `batchId`、`dataVersion` 和生成时间。

元数据使用仓库内 JSON 清单与数仓元数据表双写，接口只读取已原子发布的 current manifest。流水线在临时目录完成计算，全部检查成功后原子切换 current 指针；失败时继续提供上一成功版本。相同批次重复运行通过输入摘要和输出清单验证幂等性。

级联影响报告描述每条质量规则导致的隔离行数、受影响事实表、主题表和最终指标，使数据质量问题可以追踪到大屏与模型。

## 4. 模型生命周期

训练框架提供统一候选模型接口，至少比较随机森林、线性回归和梯度提升树。训练集与测试集按时间切分，所有候选模型共享特征版本和评估数据。选择策略先验证边界和方向性，再按验证集 RMSE 选择；若无候选通过约束，则保留上一生产模型。

模型注册表记录 `modelVersion`、`featureVersion`、`batchId`、算法、参数、指标、训练区间、制品路径和状态。预测输出覆盖 1、6、24 小时及配置的更长周期，包含点预测、上下置信界、预计会话数、预计空闲桩、生成时间和模型版本，并将空闲桩限制在有效桩数范围内。

漂移模块比较当前窗口与训练基线的数值分布、类别占比和预测误差，生成正常、关注、严重三级结果。准实时特征任务以增量检查点读取新订单、设备状态和天气数据；失败时不推进检查点，并保留最近成功预测。

## 5. Flask API 与访问控制

所有接口使用统一 JSON 包装：成功返回 `data`、`meta`，失败返回稳定 `error`、`message`、`requestId`。兼容现有大屏读取方式的接口在迁移期保留，但由同一服务层产生数据。

分析读取接口按公共大屏、Qt 服务端、监管/租户三类访问者划分。环回开发模式允许免认证；跨主机监听必须配置 API 密钥，使用常量时间比较并记录脱敏审计。查询参数统一限制类型、枚举、时间范围、站点数量、分页大小和响应体规模。

服务读取 current manifest，并为响应附加批次、数据版本、模型版本、生成时间和过期状态。缓存采用最后成功结果与 ETag；文件缺失、无效 JSON 或版本不完整时返回明确降级状态，不暴露绝对路径、堆栈或敏感配置。

## 6. Web 大屏

现有 Vue/ECharts 页面扩展为统一的运营大屏，保留十类核心视图，增加自动刷新、日期/区域/站点/预测范围筛选、加载/空数据/过期/错误状态和重复实例清理。所有前端依赖本地化，不请求公共 CDN。

页面提供运营、监管、租户三种视图。租户上下文由服务端授权结果决定，客户端参数不能扩大数据范围；监管视图只展示聚合信息。多租户默认以站点归属字段隔离，缺少归属的数据不进入租户视图。

视觉验收使用固定种子数据和浏览器自动化，在 1920×1080、1366×768 和全屏尺寸生成截图，并执行溢出、重叠、字体缺失、控制台错误和持续刷新内存检查。视觉基线的人工批准与像素差异结果共同归档。

## 7. Qt 用户端与管理员端

用户端保留现有距离排序作为即时结果，异步请求 1、6、24 小时或更长范围的预测。站点卡显示预测范围、生成时间、预计空闲桩、置信区间和推荐理由；预测失败时保持实时站点数据并显示不可用或缓存标识。排序可在距离、价格和低拥堵之间切换。

管理员端展示重点站点预测和正常、关注、拥堵、严重四级预警，支持预测范围、区域和等级筛选。同站点、同范围、同模型版本的预警使用稳定键更新而非重复追加。服务异常时显示离线或过期，不将缺失数据解释为正常。

调度模块根据预测负荷、桩状态和人员班次生成建议，维护模块关联开放告警和设备状态，扩容模块基于持续高利用率、排队压力和可用容量生成解释性建议。所有建议为只读决策支持，不自动执行设备控制或人员排班；管理员确认后才进入现有管理动作或导出流程。

## 8. TCP 协议扩展

现有预测、推荐、预警和状态消息保持兼容，并增加模型对比、漂移状态、调度建议、维护建议、扩容建议和监管摘要消息。所有请求使用非零 `requestId`，响应复用请求编号，并沿用现有会话角色检查、重复请求检测、长度限制和错误码。

Qt 服务端继续作为客户端唯一业务入口。分析适配器执行有限超时、响应校验、查询键缓存和过期标记；调用运行在线程池中，不阻塞充电进度推送和管理员控制消息。

## 9. 安全、审计与隐私

分析快照只保留业务必要字段；手机号使用不可逆标识或聚合值，钱包流水和精确用户轨迹不进入大屏层。模型、数据、日志和密钥目录由环境检查验证权限；密钥只从环境变量或部署密钥文件读取，不提交仓库。

审计日志记录访问者类别、租户、接口、范围、结果、耗时和 requestId，不记录密钥、密码、完整个人字段或绝对敏感路径。导出、模型切换、调度确认和建议确认属于重点审计事件。

## 10. 异常处理与恢复

每层遵循“新版本完整后再发布”。数据或模型任务失败时保持上一成功版本；Flask 不可用时 Qt 使用带时间戳的最后成功缓存；没有缓存时仅分析能力降级。自动刷新采用单飞请求，避免重复计时器和并发覆盖。恢复后下一次刷新自动回到新鲜数据，并清除过期提示。

## 11. 测试与验收证据

测试分为纯函数单元测试、Spark 本地集成测试、Flask API 测试、TCP/服务测试、Qt UI 测试、浏览器视觉与稳定性测试、端到端部署测试。固定种子数据覆盖高峰、降雨、节假日、设备不可用、脏数据、文件缺失、超时、无效 JSON、未登录、越权和重复请求。

`scripts/acceptance/` 提供统一入口，生成 `artifacts/acceptance/<runId>/manifest.json`、JUnit、指标摘要、截图和日志摘要。证据目录默认不提交；仓库提交脱敏的示例报告和格式说明。需求追踪脚本校验每个编号均关联实现、测试和证据类型，只有实际成功运行的检查才标为通过。

## 12. 部署与运维

部署配置显式提供 SQLite/CSV 输入、HDFS 根目录、ADS 目录、Flask 地址、API 密钥、租户映射、刷新周期、预警阈值、模型周期和保留策略。启动脚本按环境检查、数据流水线、模型、Flask、Qt 服务端顺序执行，并提供健康检查与停止脚本。

Hadoop/Spark 不可用的开发机可运行 Python、Flask、协议和 UI 测试，但最终验收清单必须明确外部步骤未运行。课程虚拟机执行同一验收入口后，才产生完整通过结论。

## 13. 兼容性与迁移

所有现有消息编号、第一阶段数据库表和核心界面保持兼容。新增数仓字段只追加不改义；旧 ADS 文件通过规范化适配器读取。新协议能力协商失败时客户端隐藏对应高级入口并继续使用第一阶段功能。

## 14. 交付物

最终交付包含源码、环境与部署脚本、数据字典、数仓说明、API/TCP 协议、模型卡、测试用例、质量报告、漂移报告、视觉截图、验收清单、演示说明和更新后的需求追踪矩阵。每个子项目独立提交，最终由一次全量验证提交封板。
