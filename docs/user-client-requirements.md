## 1. 责任边界

史雨函负责第 6—18 项在用户手机客户端（Linux + Qt）中的完整实现，包括：

- 页面和交互流程。
- 输入校验和本地状态管理。
- 通过 `ClientApi` 发送请求并匹配响应。
- 加载、空数据、成功、业务失败、超时和断线状态。
- 用户端功能测试和页面测试。

客户端不直接访问 SQLite，不在本地修改最终钱包余额，不自行计算最终费用，也不根据断线或请求超时推断预约、充电或订单终态。

不属于本次负责范围：需求 1—5、19—65。其他需求仅在第 6—18 项正常运行所必需时作为外部依赖记录，不纳入史雨函的交付统计。

- `🟡 部分完成`：已有页面或基础能力，但缺少完整流程或服务端联调。

## 3. 分项验收标准

### 需求 6—9：资料与钱包

- 头像只能使用有效的 PNG/JPEG，尺寸和编码大小必须符合限制。
- 昵称输入必须通过长度和非法字符校验，失败后保留原昵称。
- 充值金额限制为 1—5000 元且最多两位小数，重复提交不得造成重复入账。
- 客户端不得先行修改余额，头像、昵称和余额均以服务端成功响应为准。
- 能展示多条充值流水，并按时间倒序排列。
- 金额和充值后余额始终显示两位小数。
- 空数组显示“暂无充值记录”，不得显示为请求失败。
- 请求失败或超时后提供明确提示和重试入口。

### 需求 10—15：找桩流程

- 地址为空时不进入加载状态、不发送站点请求。
- 模拟定位和手动地址都可以作为查询入口。
- 站点距离计算和排序结果稳定。
- 站点列表和电桩详情均有加载、空数据、错误和重试状态。
- 缺失或异常字段不得导致页面崩溃或显示明显错误数值。

### 需求 16—17：地图导航

- 支持驾车和步行两种路线模式。
- 地图 URL 必须使用 HTTPS 和允许的腾讯地图域名。
- 无 Key、请求失败或 WebEngine 不可用时显示降级页面。
- 地图不可用不影响手动找桩、距离排序和站点详情查看。

### 需求 18：站点收藏

- 收藏和取消收藏操作应防止重复提交。
- 可以采用乐观更新，但请求失败必须恢复原状态。
- 页面刷新后以服务端收藏状态为准。
- 收藏站点可以从用户端入口重新打开。

## 4. 服务端依赖

以下内容需要服务端负责人确认或实现，但对应的客户端页面、状态和错误处理仍属于第 6—18 项工作：

- 头像上传和昵称修改的消息类型、字段限制及错误码。
- 钱包充值的消息类型、金额范围、幂等规则和余额返回字段。
- 充值记录查询的消息类型、分页/排序字段和流水结构。
- 电桩详情的响应字段及错误码（站点列表及收藏字段已落地）。
- 腾讯地图地址解析已按概要设计落地为服务端 `MapAdapter` 调用；Key 使用 `TENCENT_MAP_KEY` 或 `config/app.ini`，不通过协议回传。
- 收藏协议已落地为 `FavoriteToggle` 2020/2021 和 `FavoriteList` 2022/2023；最终状态由服务端返回。
