# Web 分析大屏 UI/UX 审计与实施计划

> 范围：仅 Flask 托管的 Vue 3 + ECharts Web 前端（`bigdata/dashboard`）。
> 本文是分析与实施计划，不包含应用代码变更。

## 1. 当前技术与结构审计

| 项目 | 现状 |
|---|---|
| 服务与渲染 | Flask 返回 `templates/index.html`，静态资源位于 `static/` |
| 前端框架 | Vue 3 全局生产构建，无打包器、无 SFC |
| 图表 | 本地 ECharts，页面脚本直接初始化和更新实例 |
| 路由 | 无前端路由；`view` 状态切换运营、监管、租户三种视图 |
| 页面结构 | 顶栏 → 视图标签 → 状态提示 → KPI/图表/表格或 JSON 结果 |
| 导航 | 顶部三视图按钮；预测周期另有局部分段切换 |
| 复用方式 | 当前没有独立组件文件；面板与状态样式依靠类名复用 |
| 表格/表单库 | 无第三方库；使用原生表格和按钮 |
| 主题 | 深色青蓝视觉；颜色、间距、圆角、阴影多为散落硬编码 |
| 响应式 | 主要覆盖 1500px、1400px 两档；中小桌面和窄屏策略不足 |
| 数据状态 | 已具备加载、错误、空、过期/降级提示，是可保留的良好基础 |

现有页面/视图：

1. **运营视图**：6 个 KPI、收益趋势、设备状态、小时负荷、站点排名、行政区分布、数据质量、告警、负荷预测、推荐表。
2. **监管视图**：接口结果当前主要以原始 JSON 展示。
3. **租户视图**：接口结果当前主要以原始 JSON 展示。

## 2. 主要一致性与可用性问题

### 信息架构

- 运营页所有模块视觉权重相近，主任务（负荷、预测、异常）不够突出。
- 六个 KPI 卡片占据过多首屏高度，降低单位屏幕的信息产出。
- 监管和租户视图以 JSON 为主，不适合业务人员阅读、比较和决策。
- 页面缺少统一的筛选上下文、已选条件和钻取返回路径。

### 视觉系统

- 缺少语义令牌，颜色、间距、圆角、阴影和字号难以全局一致。
- 渐变和阴影使用偏多，每个面板都像独立卡片，削弱层级。
- 业务状态色与图表序列色边界不清，跨图表的同一指标未形成稳定映射。
- 技术数据名出现在业务标题区域，影响认知效率。

### 图表

- 行政区玫瑰图不利于精确比较，类别排名应优先使用排序条形图。
- 图表的标题、单位、图例、空态和 Tooltip 缺少统一规则。
- 预测结果未形成“实际/预测/置信区间”的统一视觉语法。
- 图表没有可访问的文本摘要或表格替代，颜色仍承担过多编码责任。

### 表格与交互

- 推荐表具备粘性表头和横向滚动基础，但缺少明确排序、筛选摘要、结果计数、分页/容量策略和键盘状态。
- 顶部视图标签缺少完整 tab 语义、选中状态声明和方向键操作。
- 焦点样式不系统，键盘用户难以定位当前操作点。
- 响应式断点覆盖不足，1366、1024 和更窄窗口的内容密度不可控。

## 3. 全局视觉方向

定位为“实时运营决策控制台”，采用深色、克制、高密度的企业分析界面：

- 保留现有深色底、青色主色和蓝色辅助色，提升对比度和语义一致性。
- 使用 12 列紧凑网格，以边框和背景层级代替大阴影和装饰渐变。
- 首屏以异常、负荷与预测为主，KPI 退化为紧凑指标带。
- 强调筛选、比较、钻取和状态反馈，不引入营销式 Hero 或展示型动画。
- 继续使用 Vue 3、ECharts 和原生表格，不无故增加组件库或构建链。

完整令牌与规则见 [设计系统](../design-system/charging-analytics-web/MASTER.md)。

## 4. 页面实施依赖顺序

| 顺序 | 页面/能力 | 前置依赖 | 原因 |
|---:|---|---|---|
| 0 | 现状截图与可访问性基线 | 无 | 为改造前后比较提供证据 |
| 1 | 全局壳层、令牌、网格、状态 | 无 | 所有页面共同依赖 |
| 2 | 通用面板、图表壳、指标带、表格 | 1 | 页面不重复实现视觉规则 |
| 3 | 运营页首屏与主图 | 1–2 | 建立最复杂、最常用的模板 |
| 4 | 运营页次级图表 | 3 | 复用图表语法并校准密度 |
| 5 | 运营页推荐表与筛选 | 2–3 | 完成高密表格和筛选范式 |
| 6 | 监管视图结构化 | 1–2 | 用成熟组件替换 JSON 主视图 |
| 7 | 租户视图结构化 | 1–2 | 复用监管/运营模式 |
| 8 | 响应式、键盘与视觉回归 | 3–7 | 全页面统一验收 |

## 5. 具体实施计划

### A. 全局基础

1. 在现有 CSS 中建立语义令牌：颜色、字体、间距、尺寸、圆角、边框、层级和动效。
2. 重构页面骨架为 12 列桌面优先网格，补齐 1440、1200、960 与窄屏规则。
3. 统一标题、单位、数值、时间和空值格式；启用等宽数字。
4. 统一加载、错误、空数据、过期和降级状态；保留现有业务判断。
5. 补充可见焦点、对比度、Tab 语义、减少动效和跳转目标。
6. 建立 ECharts 基础主题和 resize/销毁约定，只改变表现层配置。

验收门槛：无接口、路由语义或数据处理变更；正文对比度 ≥4.5:1；仅键盘可切换视图和操作筛选；减少动效设置生效。

### B. 共享组件

1. 从当前 Vue 根实例中提取轻量展示组件：壳层、顶栏、视图标签、状态条、指标带、面板和空态。
2. 建立 `ChartPanel`：统一标题、单位、图例位置、加载/空/错态、摘要和表格替代入口。
3. 建立 `FilterBar`：常用筛选、更多筛选、激活条件、清除和结果数。
4. 建立 `DataTable`：粘性表头、对齐、排序、分页、溢出、行焦点和窄屏策略。
5. 共享组件接收现有数据对象，不迁移 API 请求职责，不改变返回结构。

验收门槛：同类状态和控件在三个视图一致；组件无隐式网络请求；图表和表格可在空数据、错误和过期数据下独立渲染。

### C. 页面级优化

#### 运营视图

1. 六个大 KPI 改为紧凑指标带，补充单位、变化和口径。
2. 将小时负荷/预测设为主图；统一实际、预测和区间表达。
3. 站点排名与行政区比较采用排序水平条形图；设备状态环图保留数值表。
4. 重排收益、质量、告警等次级面板，降低等权卡片感。
5. 推荐表加入可见排序、筛选摘要、总数与分页；保持接口不变。

#### 监管视图

1. 将 JSON 拆为总体合规、区域差异、异常站点和数据质量模块。
2. 严重告警和数据新鲜度置于首屏。
3. 原始 JSON 保留在默认折叠的排障区域，不再作为主界面。

#### 租户视图

1. 将 JSON 拆为经营指标、站点利用、预测、优化建议和明细。
2. 建议项结构化为优先级、影响、依据、动作和生成时间。
3. 原始 JSON 仅作为折叠排障信息。

## 6. 实施约束与验证

- 不改变业务逻辑、API 地址、请求参数、返回解析、数据加工、权限或后端接口。
- 不引入前端路由，不改变运营/监管/租户的语义和访问方式。
- 不替换 Vue 3、ECharts 或 Flask 托管方式。
- 每批实现后运行现有 Playwright 测试，并在 1920×1080、1440×900、1366×768、1024×768 和窄屏视口做截图检查。
- 覆盖正常、加载、空、错误、过期、长文本、大数值和表格溢出场景。
- 图表校验包括色盲可辨、图例换行、Tooltip 边界、resize、单位、负值与预测区间。

## 7. 本轮结论

当前前端的技术选型足以完成改造，主要问题不是缺少框架，而是缺少系统化令牌、组件边界和分析层级。建议先完成全局基础和共享组件，再按运营 → 监管 → 租户推进；不要从单张图表的局部美化开始。
