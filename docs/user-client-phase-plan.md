## 3. 与需求的差距

### P0：影响核心业务验收

- `ClientApi` 尚未覆盖资料更新、钱包、收藏、预约、活动订单、开始/停止充电和订单详情请求。
- 站点和电桩响应未完整按 requestId 建立请求上下文，缺少统一超时处理。
- 服务端推送尚未接入 `SnapshotStore` 和 `ChargingPage`。
- 充电页还没有活动订单查询、预约状态、开始充电、停止充电、结算和异常状态机。
- 预约确认页、未完成订单跳转、订单结算页尚未实现。
- 真实服务端业务处理器尚未注册，端到端业务无法验收。

### P1：影响功能完整性

- 钱包充值记录页面尚未实现。
- 收藏状态更新、失败回滚和刷新逻辑尚未实现。
- 站点详情缺少导航入口和完整的站点信息展示。
- 腾讯地图 `QWebEngineView` 页面、HTTPS 白名单和不可用降级界面尚未接入。
- 头像目前只有本地预览，尚未完成压缩后的上传报文封装。
- 用户端专用 QtTest 和页面测试尚未建立。

### P2：影响交付质量

- `UserController` 与 `ClientApi` 存在职责重复，需要确定保留一个主入口。
- 进度文档和早期实施计划存在部分过时描述，需要以本计划书为准同步更新。
- 页面代码中存在较多单行构造和业务信号连接，后续应拆分为可测试的控制器/组件。

## 4. 当前阶段目标

本阶段目标是完成“客户端可联调版本”，不要求服务端业务全部完成，但客户端必须具备完整的请求模型、页面状态模型、错误状态和模拟响应验证能力。

阶段完成标准：

1. 所有用户端需求都有页面入口或明确的不可用状态。
2. 所有计划中的消息都有客户端请求方法、响应信号和错误处理入口。
3. 充电状态严格按服务端状态展示，断线不改变订单终态。
4. 快照乱序、重复、跨订单和超时场景有自动化测试。
5. 无腾讯地图 Key 时仍可手动选站和按距离排序。
6. 服务端接口确认后，只需填写消息枚举和字段映射即可进入联调。

## 5. 执行计划

### 阶段 A：客户端 API 基础（优先）

任务：

- 统一 `ClientApi` 为用户端网络入口，确认 `UserController` 是否移除或仅保留兼容层。
- 建立 requestId 到请求类型的匹配表。
- 为每类请求增加超时定时器和失败信号。
- 统一解析 `statusCode`、`message` 和空 payload。
- 增加登录态失效后的统一处理。
- 增加未连接、重复请求和服务不可用的本地提示。

仅保留ClientApi为入口

验收：每类请求都能在模拟响应下触发成功、超时、未授权和业务错误分支。

### 阶段 B：个人资料与钱包

任务：

- 头像读取、压缩、预览和 Base64 请求封装。
- 昵称修改请求、成功回填和失败恢复。
- 钱包充值金额校验、幂等键预留和结果展示。
- 充值记录列表、空数据、加载和错误状态。
- 余额统一按整数分转换显示，禁止客户端自行修改余额。

验收：本地模拟响应可以完成资料修改、充值成功、重复充值、充值失败和流水为空等流程。

### 阶段 C：找桩和地图

任务：

- 站点卡片字段与协议统一，兼容 `priceCentsPerKwh`。
- 站点详情展示坐标、价格、桩数量和收藏状态。
- 收藏/取消收藏的乐观更新、失败回滚和重新加载。
- 站点详情增加驾车/步行导航入口。
- 接入 `QWebEngineView`，限制 HTTPS 域名白名单。
- 无 Key、网络失败或 WebEngine 不可用时显示降级界面。

验收：有 Key 和无 Key 两种配置均能启动；无 Key 时手动选站和距离排序可用。

### 阶段 D：预约、活动订单和充电

任务：

- 创建预约、取消预约和预约确认页面。
- 进入充电页时先查询活动订单。
- 无活动订单时显示空状态；有活动订单时跳转对应状态。
- 实现状态展示：已预约、充电中、停止中、对账中、待付款、已完成、异常结束。
- 接入开始充电和停止充电请求。
- 接入 `ChargingProgressPush` 和 `ChargingStoppedPush`。
- 使用 `SnapshotStore` 丢弃旧快照，10 秒无更新显示过期。
- 断线保留最后一次有效数据显示，重连后重新查询服务端状态。
- 处理余额不足、预约冲突、电桩不可用、设备故障、请求超时和服务不可用。

验收：使用固定模拟报文覆盖完整状态流转和异常分支；客户端不自行生成已完成或异常结束状态。

### 阶段 E：测试与交付

任务：

- 新增用户端 QtTest 工程。
- 测试手机号、昵称、金额和头像校验。
- 测试距离计算、稳定排序和站点字段解析。
- 测试快照递增、重复、乱序、跨订单和 10 秒过期。
- 测试页面加载、空数据、错误、断线和恢复状态。
- 更新进度文档、联调缺口和需求追踪记录。
- 使用服务端负责人确认后的字段制作端到端测试清单。

## 6. 服务端联调依赖

服务端需要在确认单中补齐并提交：

- 消息类型和枚举值。
- 请求/响应 JSON 字段及类型。
- 用户身份来源和权限要求。
- 订单、预约、电桩状态枚举及合法流转。
- 幂等键、重复请求和超时规则。
- 错误码与错误场景映射。
- 充电推送的 `orderId`、`seq`、推送间隔和停止报文。
- 测试账号、站点、电桩、余额、预约和订单种子数据。
- 测试服务器地址、端口和可复现的成功/失败报文。

具体填写位置：`docs/user-client-server-confirmation-request.md`。

## 8. 当前结论

史雨函负责的第一阶段客户端基础能力已经完成。当前项目处于第二阶段“用户端可联调版本”准备期，缺失集中在业务 API 封装、预约/充电/结算页面、地图页面和用户端测试。服务端确认单返回后，优先执行阶段 A 和阶段 D，尽快形成可验收的用户充电主流程。
