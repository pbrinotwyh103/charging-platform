# 用户端实施计划

## 审计结论

当前用户端已实现手机号校验、TCP 自动重连、手机号登录/自动注册、登录错误展示、资料读取和退出登录。`HomePage`、`ChargingPage`、`ProfilePage` 目前是占位页面，主窗口尚未接入三栏导航。

服务端当前已注册 `UserLoginRequest`、`UserProfileRequest`、`LogoutRequest` 和心跳；站点、桩详情、收藏、预约、充电、订单和钱包接口尚未在消息分发器中实现。

## 推进阶段

1. 用户端基础架构：`ClientApi` 统一请求/响应匹配，`SnapshotStore` 处理充电快照序号和过期状态，主窗口完成登录态和首页/充电/我的导航。
2. 账户与钱包：资料展示、昵称/头像编辑校验、充值和流水页面，先完成 API 封装和明确的待联调状态。
3. 附近站点：区域、地址、模拟定位、距离计算、稳定排序、站点卡片和详情页面。
4. 地图导航：配置读取、GCJ-02 坐标模型、HTTPS 白名单和不可用降级页面。
5. 预约、充电与结算：活动订单查询、状态机展示、实时快照、防旧序号、断线保留最后有效值。
6. 测试与交付：输入校验、距离计算、快照序号、状态切换和 JSON 解析测试，并更新进度文档。

## 约束

客户端不访问 SQLite、不计算最终费用或余额、不在断线时推断订单终态。服务端缺失的业务通过 API 封装和 UI 错误状态保留联调边界。
